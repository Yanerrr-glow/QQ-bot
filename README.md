# QQ 群 AI 机器人框架（NoneBot2 + NapCat）

把一个大模型接进 QQ 群，让它**像一个群成员那样聊天**

它不是"记住对话历史"的聊天机器人。所有群消息逐条落盘，被 @ 时才现场组装 prompt：
**已读的旧记录压缩成背景 + 未读的新发言原样呈现**；另外再挂一层本地长期记忆
（人物画像 / 事实 / 群事件）和一层原始记录索引（"你上周是不是说过……"能查出原话）。

> 本仓库是**脱敏后的通用框架**：真实密钥、QQ 号、群号、聊天记录、服务器地址
> 全部已剔除。仓库里附带的人设（`persona_*.txt`）是一份可直接运行的**示例人设**，
> 换成你自己的角色只需改那三个文件 + `.env` 里的 `AI_CHAT_BOT_NAME`。

---

## 1. 它有什么

**对话**

- 群里 @ 它才回，不抢话；提到唤醒词时也可能被叫出来（概率与冷却可调）
- 落盘的群聊记录按**固定间隔切分会话**，上一轮的未读自动降级为"可压缩背景" —— 这是省 token 的核心
- 一次回答里有好几个短句时逐句分次发，像真人打字
- 说「清空对话」/「重置对话」清空本会话记录

**人格**

- **人格三层，权限由文件划分钉死**：
  | 层 | 文件 | 谁能写 | 进 prompt 的位置 |
  |---|---|---|---|
  | 底层人设（它是谁） | `persona_base.txt` | **只有你**（直接编辑） | 第 1 位（最硬） |
  | 禁止事项（铁律） | `persona_forbidden.txt` | **只有你**（直接编辑） | 第 2 位 |
  | 表层人设（怎么说话） | `persona_surface.txt` | **只有自动迭代**（须过冲突闸门） | 第 3 位 |
- 自动迭代：定期反思近期对话 → 生成候选 → 逐条比对铁律 → 只写表层。碰到禁止事项**直接丢弃**
- 聊天里**没有**任何改人设的入口（改人格只能编辑文件）

**记忆**

- 长期记忆检索**完全在本地算，0 token**：n-gram 重叠 + 重要度 + 半衰期 + 被用次数
- 按会话硬隔离：私聊说的不在群里被提起，A 群的事不串到 B 群
- 身份归一到 QQ 号，所以同一个人的不同群昵称不会分裂成两个人
- 后端是 SQLite（可切回 JSON 文件），有迁移与修复脚本
- 群事件带时间窗 + 条数双重上限（**不会只增不减**）

**翻旧账**

- 每条消息建词面倒排索引，所以「上周谁说过来着」能查出原始记录，而不是给个模糊回忆

**多模态与联网**

- 图片：下载、phash 近似去重、人格打分后入库，发图前把候选图的真实画面交给模型挑
- 文件与 PDF：文本层抽字，抽不出来渲染 + OCR（扫描版）
- 联网搜索：SearXNG / Tavily / 任意 JSON 端点三种后端，带限流与防注入渲染
- 读网页正文：受限抓取（防 SSRF、限体积、超时），HTTP 被反爬拒绝时用无头 Chromium 读 DOM

**运维**

- Web 控制台（挂在 FastAPI 上）：改参数即时生效，参数存 `data/settings.json`
- NTP 时间校准（只取偏移量，不改系统时钟）
- 定时问候、主动发言（多重限流 + 冷却 + 日上限）
- `Dockerfile` + `docker compose` 服务器部署模板，含 NapCat 掉线看护

## 2. 架构

```
   QQ 客户端
        │
        │  ① NapCat 把 QQ 协议翻译成 OneBot v11
        ▼
   NapCat  ──  ② WebSocket（正向 ws://127.0.0.1:6700 或反向）
        │
        ▼
   NoneBot2（本项目, Python 3.12）
        │   插件 plugins/ai_chat
        │  ③ 每条群消息落盘 → data/chatlog_<会话>.json（带已读/未读标记）
        │  ④ 被 @ 时：已读压缩成背景 + 未读原样呈现 → HTTPS
        ▼
   DeepSeek API  →  回复沿原路回到群里
        │
        └─ ⑤ 回复后把这些未读标记为已读，机器人自己的回复也落盘
```

**正向 WS 还是反向 WS？**

| | 正向 WS | 反向 WS |
|---|---|---|
| 谁监听端口 | NapCat 监听 6700 | NoneBot2 监听 8080 |
| NoneBot2 需要暴露端口 | 不需要 | 需要 |
| 配置复杂度 | 只改 NapCat 一处 | 两边都要配对，容易被防火墙拦 |

本地跑用正向最省事（本仓库默认）。放进容器时反向更稳 —— 同网络里 NapCat 的 WS 服务端
可能只监听 `127.0.0.1`，bot 容器连不上。见 [`deploy/README.md`](deploy/README.md)。

## 3. 三步跑起来

### 第 0 步：先自检（推荐，约 1 分钟）

```powershell
python '_工具链\上手自检.py'
```

一次查完**环境 / 配置 / 端口 / 连通性**，并告诉你下一步该敲哪条命令；退出码 `0` = 可以启动。

| 参数 | 作用 |
|---|---|
| `--fix` | 顺手做能自动做的：生成 `.env`、建 `data/` |
| `--deep` | 再跑一遍语法检查与桩测试（约 1~2 分钟） |
| `--offline` | 不联网（跳过 DeepSeek 实测） |

它**只用标准库**，所以"依赖还没装"时也能跑出结论 —— 这正是它存在的意义。
`_工具链\自检.ps1` 和 `启动机器人.ps1` 调的是**同一份实现**（前者只是薄壳，不再各写一份）。

> **机器上还没装 Python？** 去 [Releases](../../releases/latest) 下载 **`上手自检.exe`**，
> **双击就能跑** —— 它自带解释器，不需要任何环境。检的仍是**你这台机器**的 Python 与 venv，
> 只是不必先有 Python 才能启动自检。
> （README 在仓库根，所以这个相对链接与仓库名、用户名无关 —— fork 出去也不会指错。）
>
> **它放在哪儿都能用**：先在自己周围找这个仓库（同级目录、下一层目录），找不到就**问你路径** ——
> 双击的人没法传命令行参数，所以这一步必须有。在里面填的值（API Key / 主人 QQ / 角色名）
> 会**先校验再写进 `.env`**：把文件路径粘进「API Key」那栏会被拒并要求重填。
>
> **发布（维护者看）**：打 tag 就会自动出 Release —— `.github/workflows/release.yml`
> 在 `windows-latest` 上现构建 `上手自检.exe`、算好 SHA256、建 Release 并附上文件：
> ```bash
> git tag v1.0.0 && git push origin v1.0.0
> ```
> 交给 Actions 而不是本地打包，是因为 exe 把 `_工具链/上手自检.py` **烤进了二进制** ——
> 本地忘了重打包就会发出旧逻辑；在 tag 上现构建，产物一定对应那一版源码。
> 另有一个 `check.yml`：每次 push / PR 跑语法检查与桩测试（只用标准库、不装依赖）。
>
> 也可以本地打：`& '.\_工具链\_打包上手exe.ps1'`（产出 `dist\上手自检.exe` 与一份 `.sha256`）。
> 二进制**不进仓库** —— 它在 git 里只增不减（每重打一次就永久多一个 8 MB 的 blob），
> 所以走 Release asset，仓库里只留打包脚本。改了 `_工具链\上手自检.py` 就得本地重打一次
> （`_工具链\_语法检查.py` 会在源码明显比 exe 新时提醒 —— 只提醒，不会让验收变红）；
> 走 tag 发版则由 Actions 现构建，不存在这个问题。

### 第 1 步：装依赖

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& '.\_工具链\安装依赖.ps1'
```

建 `.venv`（Python 3.12）并从镜像装 `requirements.txt`。
不需要镜像就传 `-Mirror 'https://pypi.org/simple/'`。

### 第 2 步：配置

```powershell
Copy-Item '.env.example' '.env'
notepad '.env'      # 填 DEEPSEEK_API_KEY=sk-xxxxxxxx，需要的话填 AI_CHAT_MASTER_QQ
```

Key 到 <https://platform.deepseek.com/api_keys> 申请。
`.env` 含密钥，`.gitignore` 已经把它排除 —— **不要手工 `git add -f`**。

### 第 3 步：起 NapCat，再起机器人

NapCat 的启动方式随平台和安装方式差异很大（Windows 注入 QQ / Docker / 独立部署），
本框架不代管它。你要保证的只有一件事：**OneBot 的 WebSocket 端口（默认 6700）在监听**。

```powershell
# 终端 A —— 自行启动 NapCat，确认 6700 起来了
# 终端 B —— 机器人
& '.\_工具链\启动机器人.ps1'
```

看到日志里出现 `WebSocket connection established` 之类的字样就是连上了，去群里 @ 它试试。

也可以一键走完（会先体检端口，再拉起机器人并打开控制台）：

```powershell
& '.\_工具链\一键启动.ps1'
& '.\_工具链\一键启动.ps1' -Stop       # 停止
& '.\_工具链\一键启动.ps1' -Console    # 只打开控制台
```

## 3.5 换成你自己的角色

仓库里附带的 `persona_*.txt` 是一份**能直接用、也建议你替换**的示例人设
（一个群聊少女角色）。框架本身与人设完全解耦 —— 换角色只需要动这几个地方：

| 要改的 | 改成什么 |
|---|---|
| `persona_base.txt` | 你的角色的**身份与性格**（它是谁、怎么说话）。这是唯一必须重写的文件 |
| `persona_forbidden.txt` | 你的角色的**铁律**。注意它是**逐条被解析**的，一条铁律能挡掉一条自动迭代的改动 |
| `persona_surface.txt` | 表层人设的初始内容。留空也可以，自动迭代会往里填 |
| `.env` 的 `AI_CHAT_BOT_NAME` | **必须**改成与人设里的角色名一致 |
| `.env` 的 `AI_CHAT_WAKE_WORDS`（或控制台「唤醒」组） | 改成你的角色名 / 昵称 |

写人设时有两条经验（详见 [`docs/设计取舍与踩坑.md`](docs/设计取舍与踩坑.md)）：

* **一次只说一个主要意思**，别写成产品说明书。极长的人设会把模型压成客服腔。
* **否定句别堆太密**。全篇都是「不许……」而几乎没有「要……」时，
  模型会变得过度克制、短到没话说。把核心几条改写成**正向行为**
  （「不写括号动作」→「直接写对白」）。

改完**不用重启**（每轮回复前重新读）；但容器部署下这三个文件是 `COPY` 进镜像的，
要 `docker compose build bot` 才生效。

## 4. 目录结构

```
.
├─ bot.py                        入口：init → 注册适配器 → 加载插件
├─ requirements.txt              依赖清单
├─ requirements-render.txt       渲染兜底（无头 Chromium）的额外依赖
├─ .env.example                  配置模板（真实配置写进 .env，不入库）
├─ Dockerfile                    Linux 容器镜像
├─ persona_base.txt              **底层人设**（它是谁）—— 只有你能改
├─ persona_forbidden.txt         **禁止事项**（铁律）—— 只有你能改
├─ persona_surface.txt           **表层人设**（怎么说话）—— 只有自动迭代会写
├─ data/                         运行时数据（不入库）
│   ├─ chatlog_<会话>.json       每会话一个，含已读/未读状态
│   ├─ chatlog_<会话>.archive.jsonl  超上限时挪过来的旧消息（归档，不删除）
│   ├─ memory.db                 长期记忆：人物画像 + 事实 + 群事件（SQLite）
│   ├─ memory_extract_state.json 记忆抽取水位线：每个会话抽到哪条了
│   ├─ msgindex.db               翻旧账：全量消息的词面倒排索引
│   ├─ session_summaries.json    会话轮次摘要：被丢弃的更早背景的回顾入口
│   ├─ settings.json             控制台改过的参数（优先级高于 .env）
│   ├─ stickers/                 表情包库：图片 + index.json
│   └─ bot.log                   启动脚本落盘的日志
├─ plugins/ai_chat/              插件本体（30 个模块）
├─ _工具链/                       本机与运维脚本
└─ deploy/                       服务器部署模板（Docker + NapCat + SearXNG）
```

### `plugins/ai_chat/` 各模块职责

| 模块 | 作用 |
|---|---|
| `__init__.py` | 三个入口：记录所有消息 / 被 @ 时回复 / 起后台任务 |
| `context.py` | prompt 八段式组装 + 记录读法 + 回复后处理（含"不许讲自己机制"过滤） |
| `chatlog.py` | 落盘、会话切分、已读未读、预算压缩、溢出归档、增量取数 |
| `memory.py` | 长期记忆：检索（本地打分）、覆盖更新、淘汰、抽取水位线 |
| `memstore.py` | 记忆存储后端：SQLite / JSON 双实现 |
| `msgindex.py` | 翻旧账：全量消息的词面倒排索引与检索 |
| `summaries.py` | 会话摘要：切分点归纳、渲染进 prompt、按会话轮次淘汰 |
| `persona.py` | 人设三层：组装、冲突闸门、表层写入 |
| `persona_iter.py` | 人格自我迭代：定期反思 → 候选 → 过闸门 → 写表层 |
| `signals.py` | 人设信号账本：**只观察**用户说过的说话方式要求，不改人设 |
| `instructions.py` | 实时指令：斜杠解析 + 自然语言兜底 |
| `introspect.py` | 机制说明：把真实配置渲染成事实（主人全量 / 他人简版） |
| `state.py` | 会话图片策略与「最近一张图」指代 |
| `stickers.py` | 表情包库：下载、去重、人格打分、随机取用 |
| `proactive.py` | 主动发言：定时掷骰 + 消息数触发 + 三重限流 |
| `greetings.py` | 定时问候：到点问早/午/晚安（落盘、不重发） |
| `attention.py` | 注意力机制：按话题相关性决定要不要接话 |
| `clock.py` | 时间来源：NTP 校准（只取偏移量） |
| `files.py` | 读消息里的文件（含私聊 file_id 换地址、PDF 分发） |
| `pdf.py` | 读 PDF：文本层抽字，抽不出来渲染 + OCR |
| `search.py` | 联网搜索：多后端、限流、防注入渲染 |
| `search_memory.py` | 搜索释义库：只沉淀"某名词是什么意思"的结论 |
| `fetch.py` | 读网页正文：受限抓取（防 SSRF / 限体积 / 超时） |
| `render.py` | 渲染兜底：HTTP 被反爬拒绝时用无头 Chromium 读 DOM |
| `mode.py` | 说话模式：按场合自动调整语气与长度 |
| `perceptual.py` | 感知层：消息的可量化特征 |
| `dsh_bridge.py` | `/dsh` 任务投递与取件（落盘 + 轮询，供本机 agent 消费） |
| `settings.py` | 可调参数（spec 表驱动 .env 默认值与 Web UI 表单） |
| `webui.py` | Web 控制台（FastAPI 路由 + 单页前端） |
| `config.py` | 不可调项与路径（含"当前时间"注入、人设来源） |

### `_工具链/` 各脚本职责与适用性

先说「适用」这一列为什么存在：这里的工具比框架本体还多，但**不是每一个都跟你有关**。
第一次读这个仓库时，先按这一列筛一遍，能省掉大量"这个到底能不能用"的试错。

| 适用 | 含义 |
|---|---|
| **跨平台** | 纯 Python，Windows / Linux / 服务器都能直接跑（个别需要 `.venv` 或 `pymupdf`，见作用列） |
| **容器内** | 也是纯 Python，但**动的是线上数据**，按文档在 `docker exec` 里跑 |
| **仅 Windows** | PowerShell 脚本（启动器 / 体检）。Linux 上请走 `deploy/` 那套 Docker 或 systemd |
| **仅作者** | 依赖作者本机的环境，克隆者通常用不到 |

| 脚本 | 适用 | 作用 |
|---|---|---|
| `诊断状态.py` | 跨平台 | 打印人设来源 / 记忆 / 图片策略的真实现状（只读） |
| `上手自检.py` | 跨平台 | **初始检测入口**：环境 / 配置 / 人设一致性 / 端口 / 连通性 / 代码完整性（`--fix` `--deep` `--offline`） |
| `自检.ps1` | 仅 Windows | 启动前体检 —— 只是 `上手自检.py` 的薄壳（退出码 0 = 可启动） |
| `_打包上手exe.ps1` | 仅 Windows | 把 `上手自检.py` 打成自带解释器的 `上手自检.exe`（约 8 MB，产物不进仓库） |
| `设置头像.py` | 跨平台 | 调 NapCat 扩展接口换机器人头像 |
| `预览问候.py` | 跨平台 | 离线预览问候文案（只调模型，不发消息、不连 QQ） |

| `_补提取.py` | 容器内 | 补历史记忆：把某段时间的 chatlog 重新提取进记忆库 |

| `_修复画像重复.py` | 容器内 | 合并记忆库里重复的人物画像，并删掉"机器人给自己建的画像"（见下方「画像重复」） |

| `_归属排查.py` | 容器内 | 归属排查：用**真实记录**重建当时的 prompt，量"它是不是读错了谁说的"（要真 Key + 真 chatlog） |

> **`persona_traits.json` 不随本仓库分发。** 这份特质注册表的 `channels` /
> `observed_bad_examples` 里含**线上真实对话原话**，发出来等于替群友公开聊天记录；
> 作者一侧的导出脚本把它整份列在「有意不同」里跳过了。**运行时不需要它** ——
> `persona.py` / `behavior.py` 都有内置回退，机器人照常跑；但两份巡检脚本需要：
> `_人设结构检查.py` 会直接报「找不到 persona_traits.json」并以**退出码 1** 结束，
> **这是有意的**（缺文件就该报错，不该报绿）。想用它们，按 `persona.py` /
> `behavior.py` 实际读取的字段自己写一份即可 —— 字段含义见 `_人设结构检查.py`
> 开头列的三张清单。`离线验证_桩.py` 同样依赖它，但那份会**自动跳过**注册表相关的
> 17 项并在结尾写明「跳过 N 组」，所以缺注册表时它仍跑得完（990 项通过、退出码 0）。

> **摘要的缺口**：摘要的触发点是**会话切分**，所以只有"功能上线之后新结束的那一轮"
> 才会被总结；上线之前盘上已有的轮次永远不会被总结，而这个缺口不会自愈。
> `_回填摘要.py` 就是补它的（先 `--dry-run` 看缺口，再去掉跑）：
>
> ```bash
> docker exec -w /app ai-chat-bot python /app/_工具链/_回填摘要.py --dry-run
> docker exec -w /app ai-chat-bot python /app/_工具链/_回填摘要.py --max-calls 100
> ```
>
> **画像重复**：控制台「人物画像」里可能出现好几个本该是同一个人的条目，甚至包括
> 机器**自己**的昵称。三个成因都在写入路径上（代码侧已修）：模型给人设角色写画像、
> 名字变体（`小明 ` 带了尾空格）解不出 uid、键被截到 24 字后长昵称分裂。
> 存量数据用这个脚本过一遍（**先 dry-run**，它会自动备份 `memory.db`）：
>
> ```bash
> docker exec -w /app ai-chat-bot python /app/_工具链/_修复画像重复.py --dry-run
> docker exec -w /app ai-chat-bot python /app/_工具链/_修复画像重复.py
> ```
>
> 它只动 `profile` 表，**facts / events 一条都不碰**；拿不准的条目（两个真同名的人之类）
> 只列出来给你判断，不擅自合并。
>
> **套件输出为什么值得单独一个脚本**：`离线验证_桩.py` 有 800 多条断言、上万行输出，
> 而控制台只保留尾部 —— 于是"到底过没过、挂在哪几条"常常看不见。
> `_跑桩验证.py` 把完整输出写进 `_selftest_full.log`，之后随便 grep。

> **两份离线验证的分工**：`离线验证.py` 查"装得起来吗"（起一遍驱动、加载整个插件包）；
> `离线验证_桩.py` 查"算得对不对"（无依赖也能跑）。改完代码两份都该跑一遍。
>
> **PDF 那三个脚本的分工**：`_PDF读取验证.py` 在本机跑（只要 pymupdf，验纯逻辑）；
> `PDF端到端验证.py` **必须在容器里跑** —— 本机通常没装 OCR，扫描版那条路只有容器里能走通：
>
> ```bash
> docker exec -e PYTHONIOENCODING=utf-8 ai-chat-bot \
>     python /app/_工具链/PDF端到端验证.py /tmp/某份.pdf
> ```

## 6. prompt 是怎么组装的

固定八段，**顺序就是优先级**（可缓存的部分在前，每轮变化的部分在后）：

```
system:
  ① 人格三层（底色 → 铁律 → 表层）
  ② 运行时风格要求      data/persona_directives.json（聊天里 /风格 改的）
  ③ 当前时间
  ④ 聊天记录的读法      **由代码保证**（context.record_legend）
  ⑤ 长期记忆           相关的事实 + 人物画像
  ⑥ 你自己的机制事实      只在真被问到时才注入（避免凭空编）

user:
  ⑦ 更早的聊天记录（已读过，压缩）＋ 刚才的新发言（原样）＋ 引用 + 文件 + 图片
  ⑧ 本次要回应的发言
```

第 ⑥ 段是**按需的**：问「你的图片机制是什么」才生成，平时一个 token 都不花 ——
这也是"机制说明不是幻觉"的实现方式。

## 7. 安全须知

部署前请认真读这几条，它们都是踩过的坑：

1. **Web 控制台没有任何认证。** 它能看全部聊天记录、改全部配置、以机器人的 QQ 身份发言。
   所以端口必须只绑 `127.0.0.1`，远程访问走 SSH 隧道。`deploy/docker-compose.yml`
   里两个 `ports` 都写死了 `127.0.0.1:` 前缀 —— **不要删掉那个前缀**。
2. **`.env` 绝不入库。** 密钥一旦进了 git 历史，删文件也没用，必须吊销重发。
   本仓库的 `Dockerfile` 也刻意不 `COPY .env`（镜像层是永久的，密钥会留在层历史里）。
3. **挂小号。** NapCat 靠注入 / 第三方客户端工作，风控态度不明朗。主号被冻结不划算。
4. **`data/` 是别人的聊天记录。** 公开等于替所有群友做一次人肉，`.gitignore` 已排除。
5. **抓网页是受限的。** `fetch.py` 挡掉回环、内网、云元数据地址
   （`127.0.0.1`、`10.x`、`169.254.169.254`），且**每次重定向都重新查**。
   改这块代码时别绕开这个检查。
6. **`/dsh` 让模型间接驱动本机 agent。** 它只认主人、只做固定动作表里的动作、
   任务文本只作为一个 argv 元素传递（不经 shell）。加动作必须同时改两侧白名单。

## 9. 这个仓库与它的"活项目"是什么关系

本仓库是一份**脱敏后的对外副本**，源自在真实群里跑着的那个项目。两者由作者一侧的
两个脚本保持对齐（都在**活项目**的 `_工具链\` 下，**本仓库没有它们**），判据不是
"逐字节相同"，而是：

> 活项目的那份文本，经**同一套脱敏映射**变换之后，应当与这里逐字符相同
> —— 除非它列在「有意不同」清单中（每一条都写了理由：对外重写过的文档、
> 含线上真实数据的分析记录、特质注册表与导出脚本自身……）。

**这两个脚本为什么不随仓库分发**：核对脚本里写着「真实值 → 占位值」的映射表 ——
表里就是真实的群号与群友昵称，发出来等于把要保护的东西一起发了。

所以这一节是**给维护者看的**，不是让你在本仓库里跑的命令：

```powershell
# 在**活项目**里跑（本仓库没有这两个脚本）
& '.\_工具链\_导出开源版.ps1'        # 生成 / 更新本副本
& '.\_工具链\_核对脱敏对齐.ps1'      # 退出码 0 = 对齐
```

核对会报三类真问题：副本缺失（忘了同步）、副本多余（在这里单方面改了没回流）、
内容有差异（既不在「有意不同」清单里、脱敏后也对不上），并直接指出第一处不同的行。
