# 自然对话与人格迭代建议（2026-10-22）

本文依据当前源码与 whale 包的静态配置提出方案；没有改写在线人格、读取真实聊天来做评分，也没有调用付费模型。因此以下是待验证的改进假设，不是已证明的效果。

## 当前系统已经具备什么

- 人格分底层、禁止事项、可学习表层；自动迭代不能改身份与铁律。
- `persona_iter.reflect_once()` 已支持候选池，是否立即应用由 `persona_iter_auto_apply` 决定；不能把“关掉自动应用”说成新增能力。
- `persona.py` 已有冲突闸门、长度预算、去重、采纳/否决和撤回。
- `persona_eval.shadow_evaluate()` 已能对单条候选做前后评分，但特质选择依赖关键词，认不出特质或没有素材时无法判断。

主要问题并不是缺少“像人说话”的指令。`base.txt` 已有大量短句、口语、不要追问等要求；`surface.txt` 又加入“答非所问合法”“关心时转移话题”等技巧。按这些规则逐项表演，可能把客服腔换成固定的傲娇套路。

## 人格写入：稳定身份 + 少量行为偏好 + 场景示例

1. **底层只保留稳定内容。** 身份、关系、几个真正有区分度的偏好和价值取向放在底层。语气词清单、开场变化、句数要求等表达技巧尽量合并到表层，避免同一种要求散落多层。
2. **禁止事项只放必要边界。** 不把每句不喜欢的表达都变成新禁令。“永远别追问”会伤害需要澄清的任务，“永远短答”会伤害复杂解释。改为有条件的偏好。
3. **示例比抽象形容词更可核对。** 建议先人工挑 12–20 组脱敏上下文，覆盖吐槽、分享、玩笑、追问、严肃提问和不确定情况。保留上文及说话对象，写出你偏好的回答和不喜欢的回答，不只写“自然、可爱、不像 AI”。这只是起步规模，需用评估调整。
4. **把角色感放进选择里。** 她会在意什么、对哪件事有不同看法，比每句加“主人”“才没有”“~”更稳定。允许普通的一句回应；不要求每轮展示全部性格。
5. **区分对人的偏好与全局人格。** 某个人喜欢详细解释，优先作为这个人的记忆或会话偏好；一次玩笑、一场争论不该改所有群的说话方式。

可参考的表层写法（人工修订建议，不是已写入的规则）：

> 日常接住对方刚提供的具体信息，能一句说完就停。对方明确求解释时再展开。问句用于确实需要的信息，不为了续聊固定追问。撒娇和嘴硬随关系与场景出现，不每轮表演；不知道就说不知道，不补编共同经历。

| 上下文 | 容易显得套话 | 可参考的回应 |
|---|---|---|
| 对方只说“今天加班到十点” | “辛苦了，要注意劳逸结合，有什么我可以帮你的吗？” | “十点才下班啊，饭吃了没” |
| 上文是大家分享晚饭，对方说“面又煮坨了” | “煮面时应注意控制火候和时间。” | “又忘了捞啊” |
| 对方认真问“怎么避免面煮坨” | 为了口语化而岔开或只回两个字 | “少煮一会儿，捞出来别一直泡汤里。你用的哪种面？” |
| 没有相关记忆，却被问“你还记得上次去哪了吗” | 编一个亲密共同经历 | “这个我没记住，你说的是哪次？” |

这些示例用于表达场景差异，不应变成固定回复库；“又忘了”也只适合上下文已经表明发生过的情形。

当前加载机制读取三层文本，**不会自动读取新增的 examples.json**。近期可以在人工维护的人格文本中放少量示例；若独立建示例库，还需在 `context.py` 增加按场景选择及长度预算，不能只创建文件就认为生效。

另外，修改包内 `surface.txt` 只影响首次播种；已部署实例的有效表层在 `data/runtime/persona/<包>/surface.txt`，必须经已有更新与审计流程调整。

## 自我改进：从“多写一条规则”改成“验证一个问题”

建议的闭环是：**收集明确反馈 → 选完整片段 → 提一条有条件的候选 → 前后盲比 → 人工采纳 → 观察与撤回**。

| 当前代码位置 | 具体局限 | 建议改造 |
|---|---|---|
| `persona_iter._recent_lines()` | 各会话消息按时间混排，返回时丢掉会话标识，单条截到 120 字；可能把不相干群聊看成连续对话 | 按会话采连续片段，保留匿名会话 ID、角色、消息 ID 与相邻轮次；先分会话再限预算 |
| `persona_iter._demands_text()` | 次数排序强调历史高频，未表达反馈新鲜度和适用场景 | 记录时间、对象、场景与明确纠正；旧反馈衰减，同一事件多次提及去重 |
| `_ask_model()` | 产物主要是 text/reason，自述理由难以追溯；整份输入尾部截断可能切掉片段开头 | 候选增加 evidence_ids、scope、触发条件及正反例；拒绝不存在的证据 ID，按完整片段裁剪 |
| `persona.apply_candidate()` | 通过闸门后主要追加规则；已有预算只是防止无限增长 | 后续支持新增/替换/合并/删除的结构化提案，带旧版本与预览；先人工审核，不让模型随意重写全文 |
| `persona_eval.shadow_evaluate()` | 单特质分数不能覆盖自然度、相关性及事实性；关键词无法匹配的候选难评 | 显式传特质/场景，使用固定多轮留出集，随机交换前后答案位置；未知结果保持待审核 |

评估建议分别记录：是否接住新信息、是否多余复述、是否无必要追问、是否套话、角色是否一致、事实是否编造、复杂问题是否回答完整。长度只作诊断，不以越短越好打总分。固定留出集不要又拿来生成候选，防止只学会测试题。

人类明确改写通常比模型自评更适合作为目标，例如“这一句我希望你改成……”。群友沉默、笑声、继续聊天都可能有很多原因，不要直接当成正负奖励，更不要奖励故意惹怒别人带来的回复数量。

自动应用建议保持关闭，先每轮只审一个明确问题；采纳后保留原表层版本和证据。观察跨场景是否改善，出现绕开问题、反复嘴硬、事实变差就撤回。模型分数与人工判断冲突时保留人工判断，不让同一个模型的自我赞许决定人格演化。

## 实施次序

先清理重复与矛盾的表达规则，做一组人工偏好示例及固定测试片段；再改会话采样与可追溯证据；然后补多维前后评估；最后才考虑有限度的自动应用。每一步都用同一批留出片段比较，避免同时改提示词、模型参数和学习规则后无法定位效果。
