# 人格包内容规范

> 这份文档回答一个问题：**人格包里的每份文件该写什么、不该写什么、写成什么形状。**
>
> 读者是写人格的人；参照样本是 [`persona/packs/example/`](../persona/packs/example/)（逐条演示本规范）。
> 结构（有哪些文件、能不能切过去）由 `验证/_人格包检查.py` 检查；**本文里带「判据」的条目，
> 同一份检查脚本都会验**——规范与检查是同一次改动的两面，不是两套说法。
>
> 相关文档：[`plugins/ai_chat/README.md`](../plugins/ai_chat/README.md)（人格包机制）、
> [`docs/文档与日志规范.md`](文档与日志规范.md)（权属与目录职责）、
> [`persona/_TEMPLATE/README.md`](../persona/_TEMPLATE/README.md)（新建包的步骤）。

---

## 1. 一个包里有什么

| 文件 | 必需 | 谁写 | 作用 | 进 prompt 的位置 |
|---|---|---|---|---|
| `_pack.json` | 是 | 人工 | 身份元数据（显示名 / 别名 / 角色名 / 唤醒词） | 不进 prompt |
| `base.txt` | 是 | 人工，**代码里没有写入口** | 底层人设：它是谁、怎么说话 | 第 1 位（最硬） |
| `forbidden.txt` | 是 | 人工，**代码里没有写入口** | 铁律：哪些说法不许出现 | 第 2 位 |
| `surface.txt` | 是 | 人工种子；运行时由自动迭代追加 | 表层模板：慢慢学会的说话偏好 | 第 3 位（最软） |
| `traits.json` | 否 | 人工 | 特质 / 通道 / 闸门关键词（**闸门的判据表**） | 不进 prompt |

**优先级就是文件顺序**：`forbidden` ＞ `base` ＞ `surface`。表层写得再花也压不过上面两层，
三条一起进 prompt 时越靠前越像"前提"。

> **命名约定**：`_` 与 `.` 开头的目录**不参与扫描**（`packs.list_packs()` 会跳过），
> 所以脚手架叫 `_TEMPLATE/`——它不会被当成"能切过去的人格"。
> 包 id 本身**不能**以 `_` 开头（`_人格包检查.py` 会拒），别把这两个规则搞混。

## 2. 三层怎么分工（最常写错的地方）

写之前先问一句：**这条是在说"我是谁"、"绝不许什么"，还是"这次学到的偏好"？**

| 内容 | 写进哪一层 | 为什么 |
|---|---|---|
| 名字、身份、称呼、性格底色 | `base.txt` | 改这些等于换人，必须人工改 |
| 说话的样子、回复长度、按场合分派的回法 | `base.txt` | 固定的说话方式，不参与自动学习 |
| 正反示例（"这样回 / 不要这样回"） | `base.txt` | 钉在底层才不会随迭代漂走 |
| 客服腔、括号动作、自我指认这类**硬禁止** | `forbidden.txt` | 它要被**逐条解析**出来做冲突判定 |
| 时间、机制、参数、图片处置这类不可谈的话题 | `forbidden.txt` | 同上 |
| "同一个问题被问第二遍时换个说法" | `surface.txt` | 这是可以慢慢变的偏好 |
| "答完就停，别加收尾问句" | `surface.txt` 或 `forbidden.txt` | 当"偏好"放表层，当"铁律"放禁止事项 |

**判据**：一条内容如果**改了它就该重启一次对话重新认识这个角色**，它属于 `base.txt`；
如果**模型自己学会也算数**，它属于 `surface.txt`。

### 三层都不该写的东西

* **机制说明**：`系统会附一句…`、`聊天记录分已读/未读`、`每轮会给你时间`。
  这些由代码按时机注入（见 `context.py` 的段结构），写进人设会在换角色时丢失，
  也会与代码版本冲突。`base.txt` 里出现"系统会 / 代码里 / prompt / 未读"这类词会被检查器提示。
* **全路径**：`persona/packs/<id>/forbidden.txt` 这种写法在换包或搬迁后指错地方。
  要引用同包文件就只写文件名（`forbidden.txt`）。
* **真实聊天原话**、真实姓名、群号、QQ 号。可发布副本会带上整个人格包目录
  （在用的那个包按例外整个跳过，见 `_工具链/发布/_导出开源版.ps1`）。

## 3. 格式硬规则（**违反就静默失效**，务必对着抄）

这一节每条都对应代码里的一个解析器。格式错了**不会报错**，只会表现为"写了没用"。

### 3.1 通用

| 规则 | 判据 |
|---|---|
| UTF-8，**不带 BOM** | 读文件一律按 UTF-8；带 BOM 的首字符会混进正文 |
| 换行 LF | 与工作区一致，避免跨平台差异 |
| `#` 开头（可含前导空白）的**整行**是注释 | `config.strip_comments()`：注释在**所有层**都不进 prompt、也不被闸门看到。行内 `#` 不是注释 |
| 小节标题只能写 `【…】` | `##` / `###` **不是**标题，会被当成正文接进上一条 |
| 不要写 `<!-- -->` | 不解析，会原样进 prompt |

### 3.2 `forbidden.txt` 专有

闸门靠 `persona.forbidden_items()` 把铁律**拆成条目**再逐条比对，所以形状要求最严：

| 规则 | 判据（代码位置） |
|---|---|
| 一条禁令 = 一行，**行首无缩进**、以 `- ` 开头 | `forbidden_items()` 只看 `raw[:1] in "-*·•"` |
| **缩进的行是上一条的续行**，不是新条目 | 同上：`raw.startswith((" ", "\t"))` → 接回 `items[-1]` |
| 想把两句话放一条，就写成"第一行 + 缩进续行" | 这是**允许**且常用的写法（whale 里就有） |
| 条目要**至少 6 个字**，否则被解析器丢掉 | `return [x for x in items if len(x) >= 6]` |
| 只有标题里带「禁止」两个字的小节，条目才被收 | `in_section = "禁止" in line` |
| 每条都要是**真禁令**（含"不 / 别 / 禁止 / 避免 / 勿 / 绝不 / 不得"之类） | `验证/_人设结构检查.py` 的"每条都真的是禁令" |
| 一行一条、别把 `- ` 写成 `* ` 或 `· ` | 检查器会对缩进的列表项给出提示 |

### 3.3 `surface.txt` 专有

表层是**唯一会被自动迭代改写**的一层，它的形状由写入路径决定：

| 规则 | 判据 |
|---|---|
| 条目一律 `- ` 开头 | `_budget_ok()` 用 `ln.strip().startswith("- ")` 数条目 |
| 用 `*`/`·`/`•` 写的条目不计数（预算会漏算） | 同上；检查器给提示 |
| **最后一个小节**必须是 `【自动学到的…】` | `_landing_ok()`：`apply_candidate` 是纯追加，末尾那一节决定新条目落在哪 |
| 模板里先留一个"会慢慢变好的方面"的小节，落点节放最后 | 见 `example/surface.txt` |
| 每条 8~200 字 | `validate_surface()` 的 `too_short` / `too_long` |

### 3.4 表层条目会过闸门（写之前先知道会被拦什么）

自动迭代产出的条目要过 `persona.validate_surface()`，**逆向表述**（"不要用客服腔"）
因为"站在铁律这一边"会被豁免，但**陈述句里顺带提到闸门词就会整条被拒**：

```text
✗ 技术参数拿不准时先说"我查一下"再回答
  → 命中禁止事项「参数」（机制与参数泄漏）→ forbidden_kw，整条丢弃
✓ 技术细节拿不准时先说"我查一下"再回答
```
> 这是**实测**踩到的：`example` 包最初就写了"技术参数"，被闸门拒收。
> 「参数」属于"机制/参数泄漏"那组闸门词（`traits.json` 的 `gate_terms`）。
> 所以写表层条目时**避开闸门词**；要提同一件事就换个说法。

另外两道检查也要留意：**身份代词**（"你其实是…"）和**与底层人设高度相似但有出入**
（`base_similar`，n-gram 覆盖 >= 0.62）——后者防的是"把底层人设偷偷改一点"，
所以表层条目**不要**照着 `base.txt` 的句子稍改一遍。

### 3.5 `base.txt` / `forbidden.txt` 里出现闸门词是**正常的**

闸门只对**表层候选**做关键词判定。`forbidden.txt` 里当然会出现"客服腔""括号动作"
这类词（它就是在规定这些），`base.txt` 的反例段里也会出现。检查器会把命中列出来供你核对，
但**不判失败**——判断标准是"这个词出现在哪一层、以什么身份出现"。

## 4. 内容写作规范

### 4.1 `base.txt`

* **第一句就报名字**，且与 `_pack.json` 的 `bot_name` **逐字一致**。
  例：`你是「示例角色」，群里的一个普通机器人，谁问你就答什么。`
  不一致的后果是 `chatlog._speaker()` 认不出它自己说过的话，它会对着自己上一轮接话（**不报错**）。
* 建议的小节：`【设定优先级】` → `【它是谁】` → `【性格底色】` → `【它和人怎么称呼】`
  → `【说话的样子】` → `【回复长度】` → `【先判断对方在干嘛，再决定怎么回】`
  → `【示例：这样回】` → `【示例：不要这样回】`。小节名可自定，**顺序有意义**（越靠前越硬）。
* **性格写到行为层**："被夸会嘴硬，但事情照样给你办好" 有用；
  "温柔体贴、元气开朗" 只是形容词，模型无从执行。
* **正反例要给全**：只有"这样回"没有"不要这样回"，等于没给边界。
  每个例子写成两行，`对方：…` / `你：…`。
* 长度参考：`whale` 的 `base.txt` 约 1860 字。它每次请求都要带上，**加之前先想删什么**。

### 4.2 `forbidden.txt`

* 开头两句说明本层定位与"用 `#` 停用"的约定（照抄 `example` 即可）。
* 按主题分小节，标题**必须带「禁止」**：`【禁止事项 · 说话方式】`、`【禁止事项 · 事实与自我】`、
  `【禁止事项 · 媒体】`。
* 一条一事，用**可判定的说法**：写"不说'作为一个AI'这类自我指认"，
  不要写"不要太机械"（后者没法判定，也进不了闸门）。
* 想临时停用：行首加 `#`。**闸门与 prompt 会同时忽略它**（这一点是刻意统一的）。
* 长度参考：`whale` 约 1230 字 / 20 条。

### 4.3 `surface.txt`

* 开头两句说明本层定位（只放可学的偏好、不能违反上面两层）。
* 1~3 个"会慢慢变好的方面"的小节，每个小节 2~4 条种子条目。
* **末尾必须是落点节**：`【自动学到的（自动迭代只写这一节，条目追加在文件末尾）】`。
* 长度预算：默认 `surface_max_chars=1500`、`surface_max_items=60`（控制台「人设」组可调）。
  超限时自动迭代会**拒绝写入**并通知你，由人来清理（它不自动淘汰）。

### 4.4 `_pack.json`

| 键 | 规则 |
|---|---|
| `id` | ASCII 字母/数字/下划线/连字符，≤32 字符，**与目录名一致**；`_` 开头是保留前缀（不参与扫描） |
| `name` | 给人看的显示名，可以中文 |
| `aliases` | **历史名与别名**。改名后旧记录靠它才认得出自己（见 §5） |
| `description` | 一句话说明，会显示在控制台的包列表里 |
| `bot_name` | **线上实际显示名**，与 `base.txt` 的自我介绍逐字一致 |
| `wake_words` | 逗号分隔；留空 = 不干预（由 `settings.wake_words` 决定） |
| `master_title` | 对主人的称呼；**留空 = 不干预**（由 `.env` / 控制台决定） |
| `enabled` | `false` 时不参与默认列表（`--all` 仍可看到） |
| `note` | 给人看的说明，不参与运行；可以写这份包为什么这么写 |

### 4.5 `traits.json`（可选，但**想管住闸门就得有**）

它只做**索引与元数据**，不复制规则正文 —— 规则文本的唯一真源仍是三层文件。

| 顶层键 | 作用 |
|---|---|
| `traits[]` | 特质列表，见下表 |
| `channels.kinds` | 说明「通道」可以是哪几层（`base` / `forbidden` / `surface` / `code`） |
| `fixed_notice_channels.items[]` | **固定系统文案**登记（`{file, match, why}`）：由代码写死、原样发出的句子。它们不属于人格语域，所以不与铁律做冲突判定；登记是为了"改了文案却忘了改登记"能被核对出来 |
| `parked` | 某条铁律被 `#` 停用时在这里声明（闸门关键词会自动跟着停） |
| `resolved_conflicts` | 已判完的历史冲突，只作考证 |

`traits[]` 每一项：

| 键 | 必需 | 说明 |
|---|---|---|
| `slug` | 是 | ASCII 标识（自示监控的报告按它分组） |
| `name` | 是 | 中文显示名 |
| `status` | 否 | 默认 `active`；写别的值表示不参与（`_人设结构检查.py` 只对 `active` 要求闸门词） |
| `description` | 推荐 | 一句话说清这个特质是什么 |
| `gate_terms[]` | **生效特质必需** | 闸门关键词：**违反它时会出现的那种说法**。缺了它，这一条对自动迭代**完全敞开** |
| `channels[]` | 推荐 | `{kind, match}`：这个特质表现在哪些地方。**`match` 必须是目标文件里的原文子串**，否则巡检报"通道指不到" |
| `output_markers[]` | 二选一 | 自示监控用的**输出特征**：从它已经说出来的话里认出这个特质 |
| `output_markers_note` | 二选一 | 说明"为什么不配输出特征" |
| `guards` | 二选一 | `{window, threshold, rules[{id,label,pattern,note}]}`：`behavior.py` 的**可数守卫**（"连续 N 条里出现 M 次就抑制") |
| `guards_note` | 二选一 | 说明"为什么不配可数守卫" |

**两条硬要求**（`_人设结构检查.py` 会判失败）：

1. **活着的铁律不能是孤儿** —— `forbidden.txt` 里每一条都必须被某个特质的 `channels`
   （`kind: "forbidden"`，`match` 是该条原文的子串）认领。
   不可测量 = 不可验证，所以"写了没人管"的禁令会被判错。
   多条铁律可以归到一个特质下（`example` 里 12 条铁律归成 7 个特质），
   也可以一条铁律被两个特质同时认领（无害）。
2. **生效特质必须有 `gate_terms`** —— 否则闸门不认识它，自动迭代可以合法地把违反它的话写进表层。

> ⚠️ **关于闸门词的一个重要事实**：代码里内置的兜底表（`persona._LEGACY_CONFLICTS`）
> **只有 10 个词**，它只是"注册表读不到时别裸奔"的保险。所以**一份真正在用的人格包
> 必须把自己的 `gate_terms` 写全** —— 指望内置表兜住你的铁律是不成立的。
> 写词的方法：把"违反这条时模型会怎么说"写下来（`example` 的 `assistant_tone` 就写了
> 客服腔、敬语、书面连接词、自我指认、括号动作、心理描写…… 11 个）。
>
> **同一批词会自动同时进 `_NEGATION` 否定白名单** —— 这是刻意的：否则
> 「不要用客服腔说话」这条最该被放行的候选会被自己的关键词误杀（实测踩过）。

**改完注册表要让进程重新读**：闸门关键词在启动时派生（`persona._active_trait_gates()`，
并且只取**注释掉的那条铁律已停用**的特质）。热切换人格会重新派生；只改注册表不换包时重启一次。

## 5. 改名与别名（最容易埋雷的一处）

改机器人显示名要**同时**改三处，少改一处就是静默故障：

1. `_pack.json` 的 `bot_name`（真源）；
2. 运行时的显示名：`settings.json` 的 `bot_name`（控制台/`/昵称` 写的）或 `.env` 的 `AI_CHAT_BOT_NAME`；
3. `base.txt` 里那句自我介绍。

**旧名字请加进 `_pack.json` 的 `aliases`。** 理由：`chatlog._speaker()` 判"这条会不会是我说的"
时会比对**机器人用过的所有名字**（当前显示名 + `aliases`）；改名前的旧记录往往缺
`bot_uid`/`is_bot` 字段，对不上就会落到"当别人说的"——它会把自己说过的话认知到别人身上。

启动日志里有一条一致性告警会替你盯着这件事：

```text
[WARNING] ai_chat | 机器人显示名（X）与人格包声明的角色名（Y）不一致 —— 聊天记录里的归属判定会退化。
```

## 6. 新增一条铁律之后要做什么

铁律**不是写完就生效**，它还要进闸门的判据表：

1. 在 `forbidden.txt` 里加条目（§3.2 的格式）；
2. 在 `traits.json` 里给某个生效特质补 `gate_terms` —— 写"违反它时会出现的那种说法"；
3. 跑这两条，**退出码都要是 0**：

   ```powershell
   python '验证\_人设结构检查.py'     # 通道一致性 / 孤儿铁律 / 闸门派生
   python '验证\_人格包检查.py'       # 包结构 + 内容格式
   ```

   `_人设结构检查.py` 会报**孤儿铁律**（没人认领的禁令）与**生效特质没有闸门关键词**。

> **改完 `traits.json` 要让进程重新读**：闸门关键词在启动时派生（`persona._active_trait_gates()`）。
> 热切换人格会重新派生；只改注册表不换包的话，重启一次。

## 7. 上线前的检查清单

```powershell
# ① 结构 + 内容格式（--strict 把警告也当失败）
python '验证\_人格包检查.py' --pack <你的包> --strict

# ② 通道一致性 / 孤儿铁律 / 闸门派生（逐包）
python '验证\_人设结构检查.py' --pack <你的包>

# ③ 热切换定点验证（换包当场生效、缓存失效、运行数据隔离）
python '验证\_人格包热切换验证.py'
```

人眼要过的四条：

- [ ] `bot_name` 与 `base.txt` 第一句里的名字**逐字一致**；改过名的话旧名在 `aliases` 里。
- [ ] 每条禁令都是**可判定**的说法，不是形容词。
- [ ] 表层条目**没有踩闸门词**（§3.4），也没在偷偷改底层人设的说法。
- [ ] 正文里没有机制说明、没有全路径、没有真实聊天原话与真实身份信息。
容器部署下同样能跑（`验证/` 整目录进了镜像）：

```bash
docker exec ai-chat-bot python /app/验证/_人格包检查.py
docker exec ai-chat-bot python /app/验证/_人设结构检查.py
```

## 8. 参照样本

[`persona/packs/example/`](../persona/packs/example/) 是**照本规范写的样本**，五份文件都能直接跑
（`验证/_人格包检查.py --pack example --strict` 与 `验证/_人设结构检查.py --pack example` 都是 0 错）：

* `_pack.json` —— 含 `aliases`/`description`/`note` 的写法；
* `base.txt` —— 九个小节的顺序、行为层的性格描写、正反例各有两条（约 970 字）；
* `forbidden.txt` —— 三个「禁止事项 · …」小节、12 条可判定禁令、一条两行写法（约 585 字）；
* `surface.txt` —— 条目形状、落点节位置、**全部条目已实测能过闸门**（5 条种子）；
* `traits.json` —— 7 个特质把 12 条铁律全部认领（0 孤儿），含 `gate_terms`、
  `output_markers` / `output_markers_note`、`guards` / `guards_note` 三种"配或不配都要写原因"的写法，
  以及 `fixed_notice_channels` 登记。

另有 [`persona/packs/assistant/`](../persona/packs/assistant/)：最小可用的中性样本
（**不带** `traits.json`，用来演示"可选文件缺席时闸门回退内置兜底表"）。
新建包时照抄 [`persona/_TEMPLATE/`](../persona/_TEMPLATE/)。
